# In-memory call graph

This document records the stage's design and historical verification. Later-stage/deferred statements describe that stage's original scope; consult [CLI.md](CLI.md), [APPLICATION_API.md](APPLICATION_API.md), and [VERIFICATION.md](VERIFICATION.md) for current behavior and final acceptance.

Stage 7 implements the Java-only `CodeGraph`, `GraphEdge`, and `GraphTraversal` contracts and the collections-based `InMemoryCodeGraph` adapter. No application query services or CLI are included.

Construct a snapshot with `InMemoryCodeGraph.fromSources(sourceUnits)`, or pass callable definitions and call sites directly to its constructor. The adapter consumes domain values only and reuses exact `MethodId` objects: overloads, constructors, nested types, and location-qualified fallback identities are not remapped.

All callable definitions become nodes, including isolated definitions. Every resolved target becomes a node, including external targets and targets of initializer calls without a caller. Resolved calls with a caller produce directed caller-to-target edges; identifiable callers are also nodes. Unresolved and ambiguous calls produce neither edges nor inferred target nodes. External nodes have no fabricated source definition. A callerless resolved call has a target node but no edge.

The graph retains only topology. Original immutable source units remain the authority for repeated call sites, locations, expressions, diagnostics, failure evidence, and definitions. Construction does not mutate them or discard call sites. Forward and reverse indexes are computed once, deduplicate repeated caller-target pairs, and contain entries for every node. Nodes and adjacency iterate lexicographically by `MethodId.value()`; edges iterate by caller then target. All exposed collections are immutable snapshots, independent of later mutations to input collections.

`contains` tests membership. `callers` and `callees` reject unknown IDs with `IllegalArgumentException`; known isolated nodes return empty sets. Direct adjacency preserves actual self-edges. `GraphTraversal.reachable(start, direction)` returns immutable minimum distances in deterministic BFS discovery order, excluding the start even through self-loops and cycles. `shortestPath(source, target)` returns an immutable node list in an optional: known disconnected endpoints yield an empty optional; unknown endpoints are rejected. A known node's path to itself contains that single node. Sorted adjacency breaks ties between equal-length routes. Both operations share one iterative BFS implementation and avoid recursive stack growth.

For D definitions, C call sites, V nodes, and E unique edges, construction uses expected O(D + C) hash indexing plus O(V log V + E log V) sorting, and O(V + E) graph storage. Adjacency lookup is expected O(1). Traversal visits each reached node and edge once, taking O(V + E) time and O(V) auxiliary space in the worst case; path reconstruction takes O(path length). `fromSources` additionally collects O(D + C) temporary input references. BFS relies on the graph contract's deterministic adjacency order.

Reachability reflects statically resolved lexical calls only. It does not expand runtime dispatch or infer reflection/DI behavior, and incomplete resolution can hide relationships. Application-level coverage reporting and structured unknown-ID outcomes remain stage 8 work.

Full verification reported 66 tests, zero failures/errors, and two skipped filesystem tests. The six new graph tests all passed. They cover indexes, duplicates and preserved source calls, isolated/external nodes, uncertain/callerless occurrences, exact identities, immutability, ordering, loops/cycles, minimum distances, shortest paths, and unknown/disconnected nodes.
